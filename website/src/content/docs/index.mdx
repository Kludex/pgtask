`pgtask` stores tasks in your database and runs them from your own processes. There is no broker, no coordinator, and no
PostgreSQL extension.

You enqueue a task in the same transaction that writes your application data. If the transaction rolls back, the task
never existed. That single property removes most of the consistency problems that queues usually introduce.

```python
async with connection.transaction():
    await create_report(connection, report_id)
    await client.enqueue_in(connection, render.request({"report_id": report_id}))
```

<CardGrid>
